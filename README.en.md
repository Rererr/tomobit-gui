# tomobit-gui

> **Tomobit is not built to use AI. Tomobit is built to grow with it.**

*日本語版: [README.md](README.md) — the Japanese README is the canonical one.*

A desktop chat GUI for [tomobit](https://github.com/Rererr/tomobit).

It is the **third renderer** — after the terminal and the face window — and an
input vessel. Conversation passes straight through `tomobit chat` (pipe mode)
and lands in the single ledger at `~/.tomobit/tomobit.db`.

**The GUI creates no new truth.** Tomo grows from the same ledger regardless of
which door you came in through.

## What it does

- **Chat** — streams a `tomobit chat` child process. "New chat" is a declaration
  of a boundary: the closing question, perception, and Tomo's remark all flow
  through the same screen
- **Speaking style** — stored in `~/.tomobit/gui.json` and injected via the
  provider's `--append-system-prompt`. The ledger stays clean
- **Memory pane** — read-only views of `connections` / `experiences` /
  `curiosity_queue`, with search and kind filtering
- **Workspace** — a bar between the log and the input box. The equivalent of
  `cd`, and it works regardless of provider (core ADR-0047)
- **Closing boundary** — the ✕ does not close immediately. It runs the core's
  boundary organs (feedback → perception → question → reflection) and lets you
  answer with buttons
- **Sidebar** — Tomo's appearance and per-provider usage/quota, drawn from
  `tomobit-face --view json`. The GUI owns no sprite grid of its own
- **Run a command from chat — off by default.** Enable it and `sh`/`bash`/`zsh`
  code blocks in Tomo's answers grow a run button. The first click opens a strip
  showing the full command and the working directory it will run in; a second
  click runs it. This is a path that executes model-authored text, and the strip
  only guarantees an *opportunity* to read — the ADR says so in those words.
  Results are never written to the conversation, the scrollback, or the ledger
  ([ADR-0007](docs/decisions/ADR-0007-run-command-from-chat.md))

There is no user profile feature.

## Setup

Requirements: **macOS**, Go 1.26+, Node + npm.

1. Install the core first — see [tomobit](https://github.com/Rererr/tomobit).
   You need a version with `status --view json` (core ADR-0039) and
   `tomobit-face --view json` (core ADR-0048); older cores degrade gracefully
   rather than crashing.

2. Build and install:

   ```sh
   go install github.com/wailsapp/wails/v2/cmd/wails@latest
   git clone https://github.com/Rererr/tomobit-gui && cd tomobit-gui
   make install          # frontend build → go install, same flags as wails
   ```

   For a distributable `.app`, use `wails build` instead
   (→ `build/bin/tomobit-gui.app`).

3. Run:

   ```sh
   tomobit-gui
   ```

## Stack

**Go (Wails v2) / React + TypeScript strict / system WebView.** The conversation
LLM is the core's provider mechanism (claude-code by default); perception stays
in the core's organs. The GUI touches neither.

## Development

```sh
wails dev      # hot reload; also drivable from a browser at localhost:34115
go test ./...
cd frontend && npm test && npx tsc --noEmit
```

End-to-end verification drives `wails dev` through playwright-core. **Never use
your real ledger for verification** — real conversations end up in logs and
screenshots. See [.claude/skills/verify/SKILL.md](.claude/skills/verify/SKILL.md).
