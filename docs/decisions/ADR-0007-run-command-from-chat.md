# ADR-0007: チャットの中からコマンドを実行する — 摩擦を外す代わりに、確認を明示的に置く

- Status: **Accepted**（2026-07-25 起草・実装）
- Date: 2026-07-25
- 関連: [ADR-0004](ADR-0004-workspace-scope.md)（Decision 1: 作業ディレクトリ =
  chat 子プロセスの `cmd.Dir`）,
  [ADR-0003](ADR-0003-session-transcript-cache.md)（会話の全文の永続は明示 opt-in）,
  本体 [ADR-0021](https://github.com/Rererr/tomobit/blob/main/docs/decisions/ADR-0021-wiring-is-not-experience.md)（配線は経験ではない）,
  本体 [ADR-0049](https://github.com/Rererr/tomobit/blob/main/docs/decisions/ADR-0049-quota-observation-is-opt-in.md)（沈黙は同意ではない）

## Context

Tomo の答えには、人が自分の手で打つためのコマンドが混ざる。`tomobit rebuild`、
`npm test`、`git log --oneline | head`。今それを実行する経路は、コピーボタンを
押し、端末へ切り替え、貼って、Enter。1日に何度も通る道で、そのたびに GUI を離れる。

「ボタンを1つ置けば済む」——そのとおりで、だから危うい。押せるようにするという
ことは、**モデルが書いた文字列をワンクリックで実行できるようにする**ということ
だからだ。

ただし、この GUI がその危険を新しく作るわけではない、という事実を先に置く。
GUI は `tomobit chat` の子プロセスを通じて claude / codex を走らせており、
**それらは既に、それぞれの許可モデルの下でコマンドを実行している**。人が読んで
いない `Bash` 呼び出しは、このボタンが無い今日も走っている。このボタンが増やすのは
実行能力ではなく、**人が自分の意思で走らせる経路**の方である。

だから問いは「実行させてよいか」ではない。**摩擦が担っていた安全を、何で置き換えるか**
である。コピー＆ペーストの往復は、遅いという理由だけで、走らせる前にコマンドを
一度は目に通させていた。ボタンはそれを消す。消した分を、明示的な確認として
置き直さないかぎり、これは機能ではなく穴になる。

---

## Decision 1: 既定 OFF。人が設定で有効にするまで、ボタンは存在しない

`~/.tomobit/gui.json` の `run_command` が `true` のときだけボタンが出る。キー無しは
OFF（`transcript_cache` と同じ tri-state で、既定は逆ではなく同じ側 —— 明示の
`true` が来るまで始めない）。

本体 ADR-0049 の「沈黙は同意ではない」をそのまま引く。実行経路は、便利さのために
既定で開けてよい種類の口ではない。アップデートで黙って生えるボタンが、次に起動した
ときには押せる状態になっている、という配り方はしない。

## Decision 2: ボタンが出るのは `sh` / `bash` / `zsh` と書かれたフェンスだけ

言語指定の無いコードフェンスには出さない。`json` や `go` にも出さない。

言語指定は**書き手の申告**であって検証ではない。だからこれは安全機構ではなく、
「これはコマンドのつもりで書いた」という宣言が無い塊を、こちらが勝手にコマンドと
みなさないための線引きである。申告が無いものを実行可能に見せるのは、こちらが
意味を付け足していることになる。

## Decision 3: 1度目のクリックでは走らない。確認を挟み、2度目で走る

押すと、その場に確認の帯が開く:

- **これから走るコマンドの全文**（複数行なら全行。折り返して全部見せ、省略しない）
- **どこで走るか** = 作業ディレクトリの絶対パス（ADR-0004 Decision 1 と同じ場所）

その帯の中の「実行」を押して初めて走る。キャンセルはいつでもできる。

これが Context で言った「置き直した摩擦」そのものである。ただし正直に書いておくと、
**この確認は、読まれなければ何も守らない**。守っているのは「読む機会が必ず1回ある」
ことまでで、読むかどうかまでは設計で強制できない。ワンクリックとツークリックの差は
安全の差ではなく、**気づく機会の差**である。それ以上のことは主張しない。

## Decision 4: `sh -c` で走らせる。パイプもリダイレクトも通す

シェルを介さず argv を分割して実行する案を検討し、退けた。

`go test ./...` は argv で足りるが、人が実際にボタンを押したいコマンド——
`tomobit chat --view ndjson | jq -c 'select(.type=="decided")'`、`git log | head`、
`grep -r foo . > out.txt`——の多くはシェルの語彙を必要とする。argv 限定にすると、
押せるコマンドが「押さなくても困らないコマンド」ばかりになり、人はコピーへ戻る。
使われない安全機構は、安全を提供していない。

そして、argv 分割は**安全を買っていない**。`sh` を argv で起動する 1 行を書けば
迂回できるからで、防いでいるのは事故ではなく素直な書き方だけである。
守れないものを守れるふりをする機構は置かない。

実行時の枠は次のとおり:

- cwd は作業ディレクトリ（未設定なら GUI プロセスの継承先 — ADR-0004 と同じ規律）
- 同時に走るのは 1 本だけ。走行中はボタンを押せない
- タイムアウトを持ち、超えたらプロセス群ごと殺して「時間切れ」と言う
- 出力には上限があり、超えた分は捨てて**捨てたことを言う**（黙って切り詰めない）
- 対話は想定しない。標準入力は即 EOF —— パスワードを待つコマンドは、
  ここで固まるのではなく即座に終わる

## Decision 5: 出力は会話に混ぜない。台帳にも書かない

実行結果は、押したコードブロックの直下にその場だけ表示する。

- **Tomo の発話にしない**: これは人が自分の手で走らせた結果であって、Tomo の
  ターンの中身ではない。ターンのブロック列（`TurnBlock[]`）に混ぜると、
  畳み込み（`turnFold.ts`）の入力も、スクロールバックの形も、
  「本体の view イベントの写し」でなくなる
- **スクロールバックに残さない**（ADR-0003）: あの全文は本体の view ストリームの
  再生であり、GUI 側の実行はそこに存在しなかった出来事である。混ぜれば、
  過去の全文表示は「そのとき本当に流れたもの」ではなくなる
- **台帳に何も書かない**: 判断の器官が学ぶのは Tomo の仕事の結果であって、
  人が自分で打ったコマンドの成否ではない。混ぜれば台帳が濁る。
  配線ですらない（gui.json に残るのはトグルだけ）

画面を離れれば消える。残したければ端末で打つ、が正しい答えになる。

## Consequences

- Tomo が「これを打って」と言ったとき、GUI を離れずに打てるようになる。
  作業ディレクトリ（ADR-0004）が効いているので、`cd` を思い出す必要も無い
- **モデルの出力を人がワンクリックで実行する経路が、この GUI に初めて開く。**
  既定 OFF・言語指定必須・確認必須の 3 枚を重ねてなお、最後に押すのは人であり、
  押した結果の責任も人に残る。この ADR はそれを軽くしない
- 出力が残らないので、「さっき実行した結果」を後から探すことはできない。
  これは Decision 5 の代償として意図的に受け入れている
- 確認の帯という UI が 1 つ増えた。既存の `details/summary` ではなく専用の帯に
  したのは、開いた状態が「まだ走っていない」ことを画面で語る必要があるため

### これが間違いだったと分かる条件

- **確認の帯が儀式になったとき。** 自分が帯の中身を読まずに 2 度目を押している、
  と気づいたら、Decision 3 は安全の主張を失っている。そのときは
  「読まなくても押せる」ことを認めた設計へ書き直す（例: 実行前に差分やパスを
  機械が名指しする、危険な語を含む行は別扱いにする）——確認の回数を増やす方向へは
  逃げない。1 回読まれないものは 2 回でも読まれない
- **押されないとき。** 有効にしたのに使っていない、あるいはコピーへ戻っている
  なら、この機能は摩擦を外せていない。Decision 2 の線引きが狭すぎる可能性を先に疑う

### Open Question

- 出力を「もう一度 Tomo に見せる」導線は持たない。実行結果を会話へ戻したいなら、
  今のところ人がコピーして貼る。自動で戻す口を作ると Decision 5 の境界が崩れるので、
  必要になってから、別の ADR で考える
