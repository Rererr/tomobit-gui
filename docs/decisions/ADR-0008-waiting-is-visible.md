# ADR-0008: 待っていることを画面で言う — 沈黙は進捗ではない

- Status: **Accepted**（2026-07-26 起草・実装）
- Date: 2026-07-26
- 関連: [ADR-0001](ADR-0001-gui-architecture.md)（Decision 1: GUIは第三のレンダラ。新しい真実を作らない）,
  [ADR-0005](ADR-0005-closing-boundary.md)（×で固まって見えた15秒の正体を前に出す）,
  本体 [ADR-0032](https://github.com/Rererr/tomobit/blob/main/docs/decisions/ADR-0032-pipe-chat-first-class.md)（view ストリームの語彙 — `ready` / `await` の note）,
  本体 [ADR-0040](https://github.com/Rererr/tomobit/blob/main/docs/decisions/ADR-0040-why-this-provider.md)（`decided` = なぜこのProviderか）

---

## Context

送信してから最初の1行が届くまで、この窓は何も言わない。

そのあいだ本体は止まっていない。タスクの知覚が走り、判断（ADR-0012 の
Thompson Sampling）が Provider を選び、`claude` や `codex` の子プロセスが起きて
初回の応答を待っている。実測で数秒から十数秒、Provider の混みようによってはもっと。

しかし view ストリームは**進捗があるときしか喋らない**。だから画面は前のターンの
ままで、送った本人からはこう見える——**窓が固まった**。ADR-0005 が「×を押してから
閉じるまでの15秒」で見つけたのと同じ形の問題が、会話の入口にも口を開けていた。

これまで「無反応でないこと」を語っていたのは2つだけだった:

- ターン枠の中の考え中ドット（`chat-turn-thinking`）— **最初のブロックが来るまで**しか出ない。
  つまり `turn.started` より前、いちばん長い沈黙の間は存在しない
- 走行中の tool 行（`turnFold` が畳まないのはこのため）— 中身が来てからの話

沈黙の長さと、沈黙が語らないことは別の問題である。長さは本体の仕事で、こちらでは
縮められない。**語らないこと**の方だけが、この窓の責任である。

---

## Decision 1: 会話の末尾に、動いているあいだだけ出る帯を1つ置く

`依頼中` / `実行中 · claude-code` / `区切り中` と、その段に入ってからの経過秒。
脈打つ丸が1つ付く。

- **場所は会話の末尾**（`.chat-log` の最後の子）。待っている人の目は既にそこにある。
  入力欄の上に固定する案は退けた: 追従スクロールの外に置くと、ログの高さを変える
  部品が2つになり、「最新へ」ボタンの浮かせ位置（既に手書きの px）が3つ目の
  マジックナンバーを要求する
- **経過秒を出す**のは、アニメーションだけに「動いている」を背負わせないため。
  `prefers-reduced-motion: reduce` で脈は止まるが、秒は刻み続ける。動きを止めた
  人から進捗の証拠まで取り上げない
- 秒の刻みは帯の部品の中で閉じる。上（App）に置くと1秒ごとにログ全体が再描画され、
  2026-07-26 の応答停止の修正（`appendBlocks` / `MessageView` の memo）で外した費用が
  そのまま戻る

## Decision 2: 段が動く合図は、すべて本体の契約から導く

GUI は「たぶんまだ走っている」を推測しない。タイマーで諦めもしない。段の遷移は
本体 ADR-0032 の語彙だけで書ける（`activity.ts` の純関数、`advanceActivity`）:

| 合図 | 意味 |
| --- | --- |
| 送信 / New chat の `/exit` | 待ちが始まる（唯一、GUI側の操作が起点になる場所） |
| `decided` | Provider が決まった — 段は変えず、名前だけ分かる |
| `turn.started` | 実行中へ。経過を数え直す |
| `ready` | 本体がプロンプトに立った = **人の番**。待ち終わり |
| `await` の note | 締めの質問 = 答える番。待ち終わり |
| `task.finished` / `task.cancelled` / `chat:exit` | 終わりの受け皿 |

**`turn.finished` では終わらせない**。ターンが閉じた後も器官は喋りうるし、split の
fold-back（本体 ADR-0028）では次のターンが続く。「Tomoが黙っている」と「人が答える番」は
別の事実で、契約に載っているのは後者だけである。載っていない方を推測で埋めると、
この帯は「たぶん」を言う部品になる。

### 初回送信の `ready` は1度だけ飲む

順序が逆になる場所が1つある。初回は **送信 → 子プロセスが起きる → `init` → `ready` →
こちらの行を読む** の順で、この `ready` は「人の番」ではなく「まだ読んでいない行の前」
である。素直に受けると、いちばん長い沈黙がまるごと空白に戻る。

`init`（ストリームが開いた）を見たときだけ、次の `ready` を1度飲む。飲むのは1度きりで、
`turn.started` が来れば理由（未読の行）も消える。実測（`wails dev` + 実 `tomobit chat`）で
`依頼中 0s → 実行中 · codex → 消える` と繋がることを確認済み。

## Decision 3: 動いていることを言う場所は1つにする

ターン枠の中の考え中ドットは**取り外した**。帯が常に出ている以上、枠の中と末尾で
2組が同時に跳ねるだけになる。

副産物として、過去セッションの再生（`viewFold` / ADR-0003）で途中で切れたターンが、
開くたびに「まだ考えている」ふりをすることが無くなった。**終わった会話は、二度と
待たない。**

締めダイアログ（ADR-0005）の「Tomoが今回を振り返っている…」にも同じ脈を添える。
あそこも器官が走る数十秒を文言だけで持たせていた場所で、直したい沈黙は同じものである。

## Consequences

- 送信から最初の1行までの沈黙が、**待ち時間**として読めるようになった。長さは
  変わっていない。変わったのは、それが仕事の時間だと分かることだけである
- 「窓が固まった」と「本当に固まった」が見分けられるようになった。帯の秒が
  止まっていれば、それは本体ではなく窓の側の事故である——**この帯は診断でもある**
- 帯が言えるのは「動いている」ことまでで、**何をしているかは言わない**。中身を語るのは
  tool 行と本文の仕事で、そこは本体が喋る（だから `turnFold` は走行中に畳まない）
- 段の判定が純関数に閉じたので、遷移の全部がテストで押さえられる。逆に言えば、
  ここに if を1つ足すたびに、それは契約のどのイベントから導かれたのかを言う義務が生じる

### これが間違いだったと分かる条件

- **帯が出っぱなしになったとき。** `ready` を出さない本体、あるいは終わりの合図を
  1つも出さずに黙る経路があれば、この帯は嘘をつき続ける（`chat:exit` が最後の受け皿だが、
  プロセスが生きたまま黙る形なら効かない）。そのときは推測のタイムアウトを足す方向へは
  逃げず、**本体が終わりを言っていない**という事実を先に疑う
- **秒を見なくなったとき。** 経過が誰にも読まれていないなら、それは動きの装飾であって
  進捗の証拠ではない。`prefers-reduced-motion` の下で何も残らなくなるので、そのときは
  別の残し方（最後の合図からの経過を文で言う等）を考える
