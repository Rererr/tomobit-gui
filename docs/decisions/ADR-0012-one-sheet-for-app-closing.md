# ADR-0012: アプリの×は、全窓の締めを1枚に集める

- Status: **Accepted**（2026-07-29 起草・本人承諾）
- Date: 2026-07-29
- 関連: [ADR-0005](ADR-0005-closing-boundary.md)（閉じる前の締め — 本ADRは追記
  2026-07-26「ダイアログは窓ごとに同時に立つ」の見せ方を置き換える）,
  [ADR-0009](ADR-0009-four-panes.md)（会話面の四分割 — 追記の「待たずに閉じるは
  窓ごと」も本ADRの2段構えで置き換える）

---

## Context

閉場の待ち合わせが Go 正本になり（ADR-0005 追記 2026-07-29）、`.closing-backdrop`
が窓基準になったことで、アプリの×では**窓の数だけ締めのダイアログが同時に立つ**
ようになった。個別の窓を閉じる場面ではこれが正しい — 他の窓は動き続けるべきだ。
しかしアプリごと閉じる場面では、人がやりたいのは「全部に順に答えて帰る」であって、
3枚のモーダルを行き来することではない。実際に使った本人から「各窓の内容要約と
Feedback を紐づけた1つの大きめのモーダルにしたい」と指摘された。

もう1つ、締めが走るのは**プロセスが生きている窓だけ**（`beforeClose` は
`livePanes` にしか `/exit` を送らない）なのに、`app:closing` イベントは宛先を
持たず全窓を締めモードに入れる。会話していない窓にも「Tomoが今回を振り返って
いる…」が出て、来ない exit を待つ顔をする — 待ち合わせからは外れているので
実害は無いが、表示が実態と食い違っている。

## Decision 1: アプリの×は App 直下の1枚に集める

`app:closing` で各窓の中にダイアログを立てるのをやめ、**App 直下の全画面モーダル
1枚**に全窓の締めを縦に並べる。アプリ全体の行為なのだから、画面全体を覆うのが
意味的にも正しい（個別窓の× — 会話面の中で答える — と New chat 確認 — 窓内
モーダル — は従来のまま）。

窓が1つでも同じ1枚を出す。分岐を増やさないためで、見た目もほぼ変わらない。

各セクションは:

```text
📁 personal-dev/tomobit — 「認証バグを直して」   ← 場所 + その窓の最初のユーザー発言
   （締め中に本体が喋った行があればここに並ぶ）
   [質問への選択肢 / 自由記述]  ← 来るまでは待ちの脈
---
（次の窓）
```

- **見出しは既にある事実の引用だけ**で作る: 働く場所（`displayDir`）と、その窓の
  最初のユーザー発言。本体がセッションの intent を最初の user 行から作るのと同じ
  発想で、「どの仕事の窓か」を一目にする。GUI が要約を**発明しない**
  （ADR-0005 Decision 2 の線はそのまま）
- 順序は `panes` の並び（格子と同じ）
- 質問は窓ごとに独立に届き、**来た窓から答えられる**。答えた窓は選んだ答えを
  添えて畳み、締めが終わった窓（chat:exit）は ✓ にする。全部が ✓ になった瞬間は
  Go の待ち合わせ（ADR-0005 追記）が閉じてくれる — 1枚は見せ方であって、
  閉じる機構には触らない

## Decision 2: 締めの走っている窓だけを載せる

`app:closing` イベントに**締めが走り始めた窓の一覧**を載せる（`beforeClose` は
どの窓に `/exit` を送れたかを既に知っている — `closingPanes` と同じ集合）。
セクションはその窓のぶんだけ作り、会話していない窓は載せない。締めモードに
入るのも載っている窓だけ — 載っていない窓はどうせ1枚の裏で、偽の「振り返って
いる…」を出す理由が無い。

## Decision 3: 「待たずに閉じる」は1枚に1つ。窓単位のスキップは「まだ言えない」

- モーダル末尾に「待たずに閉じる」を**1つ**置く（`AbandonBoundary` — アプリ全体を
  即閉じる。従来と同じ挙動で、今度は置き場所が挙動と一致する）
- 特定の窓の質問だけ飛ばしたければ、その質問の「まだ言えない」（空送信）で足りる
- ADR-0009 追記の「『待たずに閉じる』は窓ごと。加えてアプリの×に全体用を1つ」は
  この2段構えで**置き換える**: 窓ごとの放棄ボタンを増やすより、既に本体の語彙に
  ある「まだ言えない」を使う方が、覚えるものが増えない

## Consequences

- `beforeClose` が `eventBoundaryClosing` に締め対象の窓一覧を載せる
- `useChatSession` は自分が載っている時だけ締めモードに入る
- `ChatPaneHost` は窓内に `ClosingDialog` を出すのをやめ、締めの断面
  （問い・notes・回答関数）を App へ引き上げる。App がそれを1枚に集める
- 締めの1枚にもフォーカストラップ（ADR-0005 追記と同じ作法: 回答直後は器へ退避、
  Esc は塞ぎ、逃げ道は「待たずに閉じる」だけ）
- 積み残し: 締めが終わった窓の ✓ 以外の文言（「他の窓を待っている」等）は
  この1枚では不要になった — セクションが ✓ になるだけで、待たされている事実は
  他のセクションが語る
